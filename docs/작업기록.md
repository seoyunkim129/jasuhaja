## 🛠 새로 붙인 기능

### 1. 시설을 목록으로 관리

전에는 `수영장`, `다이소`가 코드에 박혀 있었다. 목록으로 바꿔서 나중에 사용자가 직접 추가할 수 있게 했다.

```js
const 기본시설 = [
  { 이름:'수영장', 색:'#3FD8C4', 그림:'수영'   },
  { 이름:'다이소', 색:'#F5A623', 그림:'쇼핑백' }
];
```

### 2. 아이콘 핀 마커

그림 파일을 따로 두지 않고 SVG를 글자로 만들어 쓴다 (data URI). Vercel에 올릴 때 챙길 파일이 안 늘어난다.

- 물방울 핀 + **흰 테두리** (마커끼리 겹쳐도 경계가 보임)
- 흰 배경 동그라미 (그림이 핀 색에 안 묻힘)
- 그림이 있으면 그림, 없으면 **앞글자** (`GS25` → `GS`, `스타벅스` → `스`)

### 3. 시설을 직접 추가 (이번 기획 변경의 핵심)

필터 바 아래 입력칸에 `GS25`를 넣으면 파란 핀에 `GS`가 찍힌다. `스타벅스`를 넣으면 보라 핀에 `스`.

- `localStorage`에 저장돼서 **새로고침해도 남는다**
- 기본 시설(수영장·다이소)은 못 빼고, 추가한 것만 `×`로 뺀다
- **6개 제한** — 시설이 늘면 지도를 열 때마다 그 수만큼 TMAP에 물어보게 된다

### 4. 네이버 지도 링크

핀을 누르면 네이버 지도로 이어진다. **리뷰·길찾기·영업시간을 네이버가 다 보여준다.**

```js
https://map.naver.com/p/search/{시설이름 + 구이름}
```

API 키가 필요 없다. 이것 하나로 **우리가 도보 시간을 계산할 이유가 사라졌다.**

### 5. 회색 점 289개 숨기기

시설을 4개 넣어보니 지도가 점으로 꽉 찼다. 조건 미달 단지 289개가 화면을 덮어 정작 봐야 할 시설이 안 보였다.

```
기본        조건 통과 단지만 (299 → 10개)
체크박스    "조건 미달 단지도 흐리게 보기"로 다시 볼 수 있음
```

데이터가 사라진 게 아니라는 걸 화면에 밝혀두는 게 중요했다.

### 6. 범례가 스스로 따라오게

범례 HTML에 색을 또 적지 않고, **지도 마커와 똑같은 함수**로 그린다. 그래서 시설을 추가하면 범례도 저절로 늘어나고, 마커와 범례가 어긋날 수가 없다.

### 7. 두 화면을 오갈 수 있게

`index.html`에 `map.html`로 가는 링크가 **하나도 없었다.** 주소창에 직접 쳐야만 지도에 들어갈 수 있었다. 세 곳에 달았다.

### 8. 수영장이 아닌 것 걸러내기

TMAP "수영장" 분류에 수영할 수 없는 곳이 잔뜩 섞여 나왔다.

```js
const 유아전용 = /키즈|어린이|유아|아동|주니어|차일드|kids/i;
const 미개장   = /공사중|오픈예정|개장예정|준비중/;
const 물놀이장 = /물놀이장|워터파크/;
const 법인명   = /주식회사|㈜|\(주\)/;
```

지도 마커 수영장 **29곳 → 19곳**.

## 🧱 막힌 것 / 어떻게 풀었나

### ⓪ 색이 겹치는 버그

시설을 추가할 때 색을 **순서대로** 물려줬더니, 하나 지웠다 새로 넣으면 색이 겹쳤다 (스타벅스와 CU가 둘 다 보라).

```js
저장.push({ 색: 추가색[저장.length % 추가색.length] })   // 겹침
저장.push({ 색: 남은색(저장) })                          // 안 쓰는 색을 고름
```

> **배운 것** — "순서대로 주기"는 지우기가 없을 때만 맞다. 지울 수 있으면 "안 쓰는 걸 고르기"로 가야 한다.

### ① 스킬의 프록시 서버가 죽어 있었다

```
https://k-skill-proxy.nomadamas.org  →  HTTP 530
```

**해결** — 스킬 안의 파이썬 코드를 읽어보니 프록시를 안 거치고 국토부에 직접 붙는 방법이 있었다. **API 키도 필요 없었다.** 이 방식을 강서·양천만으로 좁혀서 다시 만들었다.

> **배운 것** — 스킬이 안 돌아가도 그 안의 코드를 읽으면 우회로가 보인다. 스킬은 블랙박스가 아니라 그냥 읽을 수 있는 파일 묶음이다.

### ② 화면이 계속 옛 데이터를 보여줬다

CSV를 바꿨는데 화면이 안 바뀌었다. 원인이 **두 개 겹쳐** 있었다.

1. **브라우저 캐시** — 서버는 새 CSV를 주는데 브라우저가 옛 파일을 들고 있었다
2. **`.catch`가 모든 오류를 삼켰다** — `fetch(...).then(데이터담기).catch(() => 데이터담기(예비데이터))` 는 `데이터담기` 안의 오류까지 잡아서, 화면이 조용히 옛 데이터로 돌아가도 아무도 몰랐다

**해결**

```js
fetch(CSV주소, { cache: "no-cache" })            // 매번 "바뀌었나요?" 물어봄
  .then(r => r.ok ? r.text() : Promise.reject(new Error("HTTP " + r.status)))
  .catch(오류 => { console.warn(...); return 예비데이터; })   // 못 읽었을 때만
  .then(데이터담기);
```

### ③ TMAP 보행자 경로 API 하루 한도 초과

```
HTTP 429 QUOTA_EXCEEDED
```

762개 단지 × 2 = 1,524번이 필요한데 하루 한도가 약 1,000건이었다. **480개까지만 채워지고 멈췄다.**

**시도한 것** — 하버사인(직선거리)으로 먼저 걸러서 호출을 줄이려 했다. 그런데 **재보니 8%밖에 안 줄었다.** 강서·양천이 조밀해서 대부분 1,200m 안에 있기 때문이다.

**진짜 해결** — 도보 시간을 우리가 계산하지 않기로 했다. 네이버 지도 링크로 넘기면 네이버가 길찾기를 해준다. **문제 자체가 사라졌다.**

### ④ 지도 API 3사 비교 (중요)

## 🔧 코드 정리 (기능 변화 없음)

`index.html`(목록 화면)과 `map.html`(지도 화면)이 완전히 다른 파일인데,
필터 조건을 판단하는 `조건통과()`와 `시간바꾸기()` 함수가 **글자 하나 안 틀리고 똑같이** 두 파일에 복사돼 있었다.

나중에 조건을 하나 바꿀 때 한쪽만 고치고 다른 쪽을 깜빡하면, 목록 화면과 지도 화면이 서로 다른 기준으로 단지를 보여주는 눈에 안 띄는 버그가 생길 수 있었다.

**해결** — `공통.js` 파일 하나로 합쳐서 두 화면이 같이 불러쓴다.

```html
<script src="papaparse..."></script>
<script src="공통.js"></script>   ← 새로 추가
```

`다시그리기()`는 화면마다 그리는 방식이 완전히 달라서 (카드 vs 지도 마커) 각자 파일에 그대로 뒀다. **똑같은 코드만** 합쳤다.

### 과정

1. 깃허브 저장소 생성 (비공개) → `github.com/seoyunkim129/mulddae`
2. `package.json` + `scripts/키파일만들기.js` 추가
   - `tmap-key.js`는 `.gitignore`에 걸려 있어 깃허브에 없다
   - Vercel의 환경 변수(`TMAP_KEY`)에서 값을 읽어와, 배포할 때마다 그 파일을 새로 만들도록 했다
3. Vercel에서 깃허브 저장소 Import → `TMAP_KEY` 환경 변수 등록 → Deploy
4. 확인: 앱키 정상 주입, 지도·데이터 파일 전부 정상, GS25 같은 사용자 추가 시설도 실제 배포본에서 작동 확인

### 막힌 것

**① 배포 직후 URL이 로그인 화면으로 튕겼다**

Vercel이 만든 임시 배포 URL(`mulddae-bwbm0zol4-...`)이 `vercel.com/sso-api`로 리다이렉트됐다. 원인을 찾아보니 이건 **버그가 아니라 Vercel의 기본 배포 보호 기능**이었다. 그런데 실제로는 그 URL이 아니라 프로젝트의 정식 도메인(`mulddae-cyan.vercel.app`)이 따로 있었고, 거긴 처음부터 정상이었다.

> **배운 것** — Vercel이 배포 직후 보여주는 URL이 항상 최종 주소는 아니다. Domains 탭에서 진짜 주소를 확인해야 한다.

**② `공통.js`가 curl로는 404였다**

`curl`로 확인하니 한글 파일명(`공통.js`)이 404였다. 그런데 이건 curl이 한글을 인코딩 안 하고 그대로 보내서 생긴 착시였다. **실제 브라우저는 `공통.js`를 `%EA%B3%B5%ED%86%B5.js`로 자동 변환해서 요청**하기 때문에 진짜 사용자한텐 문제가 없었다.

> **배운 것** — 도구로 확인한 결과가 항상 사용자가 겪는 것과 같지 않다. 도구의 한계인지 실제 버그인지 구분해야 한다.
