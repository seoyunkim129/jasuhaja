  - 💬 **크레딧을 아끼려고 모델을 Sonnet↔Opus로 바꿨다.** 불필요하게 긴 조사·출력은 피한다.
- **사용자가 싫어하거나 원하지 않는 방향**
  - 기능이 계속 얹히면서 "이걸 누가 왜 쓰지?"로 길을 잃는 것. 실제로 두 번 큰 위기가 왔다(9/12, 9/19). 그때마다 **"원래 뭘 원했는지"로 돌아가 물어보는 게 효과가 있었다.** 새 기능을 얹기 전에 그게 원래 소원에 닿는지 먼저 본다.
  - "이미 있네" 같은 경쟁사 발견에는 크게 좌절한다. 조사 결과는 솔직하게 말하되 ("배운 것"과 "아직 비어 있는 자리")를 함께 준다. 사용자는 위로만 받는 걸 좋아하지 않고, **결정적인 사실을 직접 확인해서 알려주는 걸** 신뢰했다.
  - 어려운 선택지를 잔뜩 던지는 것보다 **추천 하나 + 이유**를 원했다("빨리 추천해줘").
  - 디자인보다 **기능이 먼저**(카공카페 기획에서 명시).
- **설명 방식**: 비유 + 그림(코드블록 도식) + 표. 결론을 먼저. 사용자는 화면 스크린샷으로 단계별 안내를 받는 데 익숙하다(Vercel·GitHub·TMAP 대시보드 모두 그렇게 진행함). 내가 못 보는 화면(대시보드)은 **추측하지 말고 스크린샷을 부탁**했다. 내가 틀린 안내(도메인 제한 기능이 있을 거라고 한 것, 깃허브 연결 문제로 짐작한 것)는 사용자가 스크린샷을 보여준 뒤 바로잡았다. 틀리면 짧게 인정하고 넘어간다.

## 부록 C. 환경·작업 함정

- Windows 콘솔이 cp949라서 파이썬 출력이 깨진다 → `sys.stdout.reconfigure(encoding="utf-8")`. 파일 저장 자체는 정상이니 출력만 깨져도 놀라지 말 것(`UnicodeEncodeError`가 저장 뒤에 나기도 했다).
- **bash 히어로독(`<<'PY'`) 안의 파이썬에서 `\n` 이스케이프가 실제 줄바꿈으로 파일에 들어가** 자바스크립트 문법 오류를 낸 적이 있다(9/19 이전). 여러 줄 문자열은 JS 백틱으로 쓰는 게 안전하다.
- `$TMPDIR`는 호출마다 값이 달라질 수 있다(한 번 파일을 못 찾았다). 임시 파일은 세션 scratchpad 경로를 명시해서 쓴다.
- 한국 공공기관 사이트는 인증서 오류(`curl -k`)나 EUC-KR 인코딩이 흔하다.
- 로컬 확인: `.claude/launch.json`의 `mulddae` 서버(포트 8000). 다른 세션이 이미 8000을 쓰고 있을 수 있다.
- 브라우저 캐시: `?v=숫자`. `index.html` 첫 화면의 배포 확인은 `/`가 맞다(`/index`는 안 됨).
- 파일에 한글 파일명(`공통.js`, `키파일만들기.js`, `도보시간채우기.py`)이 있다. 그대로 두었고 문제 없다.
- 코드 스타일: 함수·변수를 한국어로 쓰고 주석에 "왜"를 적는다. 사용자가 배우는 프로젝트라 이 스타일을 유지했다. 수정은 `python` 치환 스크립트 + `assert`로 "기대한 원문이 있는지" 확인하는 방식으로 해서 조용한 실패를 막았다.
