# 물때 — 기획을 두 갈래로 나눔

## 왜 바뀌었나

원래 소원은 "다이소랑 수영장이 둘 다 도보 거리 안에 있는 단지 보기"였다. 오늘 하루 기능을 계속 얹다가 "이걸 누가 왜 쓸까"에서 길을 잃었는데, 다시 원점으로 돌아가 보니 **원래 소원 자체는 이미 완성돼 있었다** (mulddae-cyan.vercel.app).

대신 기획을 더 명확하게 하려고 **두 개로 쪼갠다.** 둘 다 "지도가 핵심 뼈대"라는 틀은 그대로 유지한다.

---

## 프로젝트 A — 수영장 전용 집 찾기 (기존 물때를 단순화)

**바뀌는 것**: 다이소 조건을 뺀다. **수영장 도보권만** 남긴다.

| 항목 | 내용 |
| --- | --- |
| 장소(수영장) | 고정 — 필터 조건은 수영장 하나뿐 |
| 지도 범위 | 넓게 유지 (지금처럼 강서구·양천구, 필요하면 더 넓혀도 됨) |
| 데이터 | 기존 국토부 실거래가 + TMAP 수영장 검색 **그대로 재사용** |
| 코드 작업량 | 적음 — 다이소 관련 필터·표시만 빼면 됨 |

**한 줄 요약**: 장소는 고정, 범위는 넓게.

---

## 프로젝트 B — 카공하기 좋은 카페 지도 (신규)

**목적**: 마포구 연남·망원·합정 일대에서 "카공(카페에서 공부·작업)"하기 좋은 카페를 시각화한다.

| 항목 | 내용 |
| --- | --- |
| 대상 | 카페 (개인카페 + 프랜차이즈 **전부 포함**) |
| 지역 | **의도적으로 좁게 한정** — 연남·망원·합정 인근. 마포구 전체가 아니다 |
| 우선순위 | 이번 단계는 **디자인보다 기능이 먼저** |

**한 줄 요약**: 장소는 필터링, 범위는 좁게. (프로젝트 A와 정반대 구조)

### 핵심 설계 — "왜 카공하기 좋은지"가 보여야 신뢰가 생긴다

그냥 "여기 좋아요"라고만 하면 아무도 안 믿는다. 그래서:

1. **화면 상단에 판단 기준을 먼저 공개**한다 (기준을 숨기지 않는다)
2. 카페를 누르면 → **기준별 점수**를 각각 보여준다

**후보 기준 (오늘 나온 것)**

- 분위기
- 사장 눈치 (오래 있어도 눈치 안 주는지)
- 콘센트 (자리마다 있는지)
- 여러 층 여부

**카페 클릭했을 때 보이는 것 (예시)**

```
○○카페
  분위기      ★★★★☆ (4/5)
  사장눈치    ★★★☆☆ (3/5)
  콘센트      ★★★★★ (5/5)
  여러 층     있음
```

### 아직 결정 안 된 것 (다음에 정하기)

**점수를 어디서 가져올지** — 오늘 두 가지 안이 나왔는데, 둘 다 확정은 아니다.

1. **네이버 리뷰 감성분석** — 리뷰 텍스트에서 "카공하기 좋다"류 표현을 뽑아 점수화
2. **특정 스레드(Threads) 계정 크롤링** — 지역별로 카공 카페를 추천하는 계정의 게시물을 가져와 반영

두 방식 다 장단점이 있고(①은 규모는 크지만 감성분석 정확도 문제, ②는 정확하지만 그 계정이 다룬 카페로 범위가 제한됨), 이건 다음 세션에서 더 얘기하고 정한다.
