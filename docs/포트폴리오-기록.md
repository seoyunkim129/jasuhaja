> `작업기록.md`가 "무엇을 만들었나"를 적는다면, 이 문서는 **"누가 왜 그렇게 결정했나"** 를 적습니다.

## 1. 결정 기록

내가 내린 결정과, 그 결정이 실제로 무엇을 바꿨는지.

### D1 · 조건을 하나로 줄였다 (2026-09-19)

원래 기획은 "다이소와 수영장이 둘 다 도보권인 아파트 단지 찾기"였다.
조건이 둘이면 결과가 너무 적게 남고, 무엇보다 **내가 진짜 알고 싶은 건 수영장 하나**였다.
다이소 조건을 없애고, 다이소는 지도에서 직접 추가하는 기능으로 내렸다.

**바뀐 것** — 프로젝트의 정체성이 "집 찾기"에서 "수영장 찾기"로 옮겨갔다.

### D2 · "시간표 없으면 아무도 안 쓴다" (2026-09-19)

AI는 시간표 수집이 오래 걸리니 **먼저 가볍게 만들자**고 권했다. 나는 기각했다.

> 시간표를 넣어야지 사람들이 쓸듯.. 현실적으로???;;; 구역을 우선적으로 좁히더라도,,,!!!!

이미 apuapu.kr이라는 경쟁 서비스가 시간표를 다 갖고 있는 상황이었다.
시간표 없는 지도를 만들면 **거기 놔두고 굳이 여기 올 이유가 없다.**

**바뀐 것** — 범위를 전국에서 마포구로 좁히는 대신 시간표를 채우는 쪽을 택했다.
AI도 판단을 바꿨다: *"시간표 넣는 게 맞아요. 제가 '가볍게'를 권했는데, 시간표 없으면 apuapu 놔두고 굳이 여기 올 이유가 없죠."*

### D3 · 게임을 멈추고 본 프로젝트로 돌아왔다 (2026-09-24)

웹캠 수영 게임(유입용 미끼)을 2단계까지 만들다가 중단했다.
재미있는 곁가지보다 **본체가 아직 안 끝났다**는 판단.

**바뀐 것** — 게임은 `수영게임.html`로 남겨두고 커밋하지 않았다. 본 프로젝트의 현황 점검부터 다시 시작.

### D4 · 정답표부터 만들기로 했다 (2026-09-24)

"키워드 방식 vs AI 방식" 비교 실험을 하려는데, **비교할 자가 없었다.**
AI 토큰을 받아 실험을 먼저 돌리는 대신, 사람이 읽고 매긴 정답표를 먼저 만드는 순서를 택했다.

**바뀐 것** — 이 결정 덕분에 "키워드 방식은 정밀도 86% / 재현율 35%"라는 숫자가 나왔고,
문제가 오탐이 아니라 **누락**이라는 걸 알게 됐다. 측정 없이 AI를 붙였다면 엉뚱한 곳을 고쳤을 것이다.

## 2. 검증한 순간

AI가 한 말을 그대로 받지 않고 되묻거나 직접 확인한 기록. **이 프로젝트에서 가장 중요한 부분.**

### V1 · 앱키를 AI에게 보여주면 안 되는 것 아니냐

TMAP 앱키를 설정하는 과정에서, AI가 묻기도 전에 내가 먼저 물었다.

> 앱키는 보안상 너한테 보여주면 안되는거 아니냐

**결과** — 맞는 판단이었다. 이후 앱키는 `tmap-key.js`(gitignore), 네이버 키는 `.env.local`,
배포 환경에서는 환경변수로만 관리하는 구조가 자리잡았다. 화면 캡처를 보낼 때도 키를 가리는 습관이 생겼다.

### V2 · 경쟁사를 내가 먼저 찾았다

AI가 시장 조사를 시켜서 한 게 아니라, 내가 직접 찾아보다 apuapu.kr(어푸어푸어푸푸)을 발견했다.

> 아씨 짜증나네 어푸어푸어푸푸 (apuapu.kr) 이게 완전 내가 하고자 하는게 다 반영이 되어있어
> 얘도보니까 리뷰를 담아놨는데 어떻게 한거지 대체 (...) **이거랑 다르게 내가 디벨롭 할 수있는게 뭐가 있을까?**

**결과** — "이미 있는 걸 또 만드는가"라는 질문이 프로젝트 내내 기준이 됐다.
조사해보니 apuapu는 전국 839곳에 시간표·요금·레인·수심까지 갖췄지만 **리뷰는 사실상 1개, 커뮤니티 글 0개**였다.
즉 후기 데이터는 아무도 못 가진 자리라는 걸 알게 됐고, 나중에 이게 왜 그런지도 밝혀졌다(V3).

### V3 · "본문을 주지 않는다고?" — 묻혀 있던 한계를 끄집어냈다

AI가 만든 정답표 문서에 이런 문장이 있었다.

> 네이버 검색 API는 카페 본문을 주지 않습니다. 아래 판정은 전부 제목과 짧은 요약문만 보고 내린 것이라…

나는 여기서 멈췄다.

> 잠깐 이게 뭔소리에 본문을 주지 않는다고? 그럼 너가 판정하는게 저 3줄에 대한 분석이 다야???

**결과 — 이 프로젝트에서 가장 큰 발견으로 이어졌다.**

1. 실제로 재보니 네이버가 주는 요약문은 **평균 142자, 앞뒤가 `...`로 잘림**
2. 즉 별점 시스템은 데이터 부족으로 **근본적으로 불가능**했다
3. 대안을 조사한 끝에 **구글 지도 리뷰는 본문 전체 + 별점**을 준다는 걸 찾음
4. 경쟁사 apuapu의 리뷰가 1개뿐이었던 이유도 설명됨 — 같은 벽에 막혔던 것

AI는 이 한계를 알고 문서에 적어놓긴 했지만 **지나가듯 적었고**, 그게 프로젝트의 근간을 흔드는 문제라는 걸 강조하지 않았다.
내가 그 한 문장을 붙잡지 않았다면 잘못된 전제 위에서 계속 작업했을 것이다.

### V4 · 순서가 거꾸로인 걸 잡아냈다

AI가 Hugging Face 토큰을 발급받으라고 안내하던 중이었다.

> 토큰도 아직 안받았는데 잠만 일단 뭐 리뷰가 있어야 뭘 분석할거 아님 기다려

**결과** — 맞는 지적이었다. 분석할 데이터가 확보되지 않은 상태에서 분석 도구부터 붙이는 건 순서가 틀렸다.
토큰 발급과 트랜스포머 실험을 보류하고, 데이터 출처 문제부터 해결하는 쪽으로 방향을 돌렸다.

### V5 · "도구의 한계인가, 정책 판단인가"를 구분해 물었다

AI가 네이버 크롤링을 거절했을 때, 나는 그게 능력 문제인지 판단 문제인지를 물었다.

> 그럼 코덱스도 못하는건 마찬가지 인거지

**결과** — 답이 둘로 갈렸고, 그 구분이 중요했다.
- **API가 142자만 주는 것**은 네이버 서버가 정한 것이라 어느 도구를 써도 같다 (기술적 한계)
- **크롤링 거절**은 AI의 판단이고, 다른 도구는 해줄 수도 있다 (정책 판단)

그리고 그 위험은 AI가 아니라 **내 계정·내 IP·내 포트폴리오**가 진다는 것도 확인했다.
"안 되니까 포기"가 아니라 "왜 안 되는지 알고 선택"이 됐다.

### V6 · 비용과 보안을 먼저 물었다

로컬 서버를 켜둔 채 카페에서 작업하던 중.

> 이거 서버 끄는게 나은거니 아니면 그대로 둬도 비용 무관해?

**결과** — 비용은 0원이었지만, 확인하다 보니 **`python -m http.server`는 기본적으로 같은 와이파이의 다른 사람도 접속 가능**하다는 걸 알게 됐다.
그 폴더에는 TMAP 앱키 파일이 들어 있었다. 이후로는 `--bind 127.0.0.1`을 붙여 내 컴퓨터에서만 열리게 한다.
묻지 않았으면 몰랐을 문제였다.

### V7 · AI에게 "추측하지 말라"고 명시적으로 요구했다

세션이 바뀌어 맥락이 끊겼을 때, 나는 AI에게 현황 보고서를 요구하면서 **추측을 금지하는 조건**을 걸었다.
전문은 아래 P1 참고.

**결과** — AI가 "이미 구현됐다고 단정"하는 대신 파일과 Git을 직접 확인하고,
`실제 구현된 것 / 문서만 있는 것 / 미구현`으로 나눠 보고했다.
그 결과 **"새벽 4시 자동 실행"이 설정 파일조차 없다**는 것, **"Hugging Face 분석"이 한 번도 실행된 적 없다**는 것이 드러났다.
조건을 걸지 않았다면 "대체로 잘 되고 있다"는 답을 받았을 가능성이 높다.

## 3. AI가 틀렸고 내가/측정이 잡아낸 것

포트폴리오에서 이 항목은 솔직할수록 강하다. "AI를 검증 없이 믿지 않았다"의 증거이기 때문.

| # | AI가 한 말 | 실제 | 어떻게 드러났나 |
|---|---|---|---|
| 1 | "직선거리로 미리 걸러내면 API 한도 문제가 풀린다" | 실제 절감 **8%**. 문제 해결 안 됨 | 직접 측정 |
| 2 | "TMAP에서 도메인 제한을 걸어라" | TMAP에는 **도메인 제한 기능 자체가 없음** | 내가 설정 화면에서 못 찾아서 캡처를 보냄 |
| 3 | "시설 정보는 수기로 모으는 수밖에 없다" | robots.txt 확인해보니 **크롤링 가능**했고 시간표도 HTML에 있었음 | 확인 요구 |
| 4 | "키워드 분석의 문제는 오탐(헛다리)이다" | 오탐 1건, **누락 11건**. 문제는 정반대였음 | 정답표로 측정 |
| 5 | 네이버 API를 대안으로 제안하며 본문을 못 받는다는 걸 강조하지 않음 | 별점 시스템의 전제가 무너짐 | V3 — 내가 되물음 |

> 5번은 특히 중요하다. AI는 거짓말을 한 게 아니라 **중요한 한계를 사소하게 적었다.**
> 사실 여부만 확인하는 걸로는 부족하고, "이게 프로젝트에 어떤 의미인지"를 내가 따져야 한다는 걸 배웠다.

## 4. 잘 통한 프롬프트 (전문)

### P1 · 현황 보고서 요구 프롬프트 (2026-09-24)

**왜 좋았나** — ① 추측을 금지하고 근거를 요구했다 ② 결과를 3단계로 나누라고 구조를 지정했다
③ 비밀키를 출력하지 말라는 조건을 걸었다 ④ 한꺼번에 고치지 말고 단계별로 확인하라고 제한했다
⑤ 답해야 할 질문을 번호로 못박았다

```text

직접 확인해서 다음 세 가지로 구분해 주세요.

1. 실제 코드에 구현되어 있는 것
2. 문서나 기획만 작성된 것
3. 아직 구현되지 않았거나 검증되지 않은 것

업무가 방대하다면 한 번에 모두 수정하지 말고, 필요한 작업부터 단계별로 나와 확인하면서
진행해 주세요.

검색 결과의 제목·요약만 분석하는 것인지 명확히 확인해 주세요.

확인되지 않은 내용을 추측하지 말고 파일과 실행 결과를 근거로 답해 주세요.
```

**실제 결과** — 이 프롬프트 하나로 다음이 드러났다.
- 새벽 자동 실행: **설정 파일 자체가 없음** (문서에만 존재)
- Hugging Face: 코드만 있고 **한 번도 실행된 적 없음** (토큰 미발급)
- 죽은 코드 발견: `공통.js`, `danji.csv`는 어느 화면도 불러쓰지 않음
- 배포본과 로컬이 동일하다는 것을 바이트 단위로 확인

### P2 · 단계별 정지를 강제한 프롬프트 (웹캠 게임, 2026-09-19)

**왜 좋았나** — AI가 4단계를 한 번에 쏟아내지 못하도록 막고, 각 단계의 **검증 기준을 내가 정했다.**

```text
아래 4단계를 순서대로 진행하되, 각 단계가 끝나면 멈추고 내가 브라우저에서 직접 확인할 때까지
다음 단계로 넘어가지 마. 각 단계마다 내가 뭘 보면 성공인지 알려줘.

1단계 — 웹캠 + 포즈 인식
  검증: 내가 팔을 움직이면 점이 따라오고, 숫자가 실시간으로 바뀐다.

2단계 — 스트로크 판정 (여기가 제일 중요)
  임계값과 쿨다운은 화면 슬라이더로 실시간 조절 가능하게 해줘. 내가 튜닝할 거야.
  검증: 팔을 정확히 10번 저으면 카운터가 정확히 10을 가리킨다. 가만히 있으면 안 오른다.

3단계 — 레이스 게임
  검증: 열심히 저으면 이기고, 대충 저으면 진다.

## 원칙
- 단계마다 최소한의 코드로. 나중에 쓸지도 모르는 기능/추상화/설정 옵션 금지.
- 판정 로직(2단계)은 함수 하나로 분리해서 내가 직접 읽고 고칠 수 있게 해줘.
- 시작 전에, 내 요청에서 애매하거나 네가 가정하고 넘어간 부분이 있으면 먼저 말해줘.

## 기술 스택 (이걸로 해줘, 다른 제안이 있으면 먼저 말해줘)
- 단일 HTML 파일 1개. 빌드 도구/npm/프레임워크 없이 CDN 스크립트만 사용.
- 최신 CDN 경로와 모델 URL은 네가 확인해서 정확한 걸 써줘.
```

**실제 결과** — AI가 **가정 9개를 먼저 꺼내놓고** 시작했고, CDN 주소를 실제로 요청해 200 응답을 확인한 뒤 코드를 썼다.
"판정 로직을 함수 하나로 분리"를 요구한 덕에, 나중에 내가 직접 읽고 고칠 수 있는 코드가 나왔다.

### 프롬프트에서 반복적으로 통한 것 (정리)

| 기법 | 문구 예시 | 효과 |
|---|---|---|

## 6. 제약 안에서 한 설계 결정

"못 했다"가 아니라 "이런 제약을 확인하고 이렇게 설계했다"로 적을 것들.

| 제약 | 확인 방법 | 설계 결정 |
|---|---|---|
| 네이버 카페 크롤링 금지 | robots.txt 직접 확인 (`Disallow: /` + AI/RAG 목적 금지 명시) | 크롤링 대신 공식 검색 API 사용 |
| 네이버 블로그도 금지 | robots.txt에 `ClaudeBot: Disallow: /` 명시 | 본문 수집 포기 |
| 네이버 API는 요약문 142자만 | API 응답 100건 길이 측정 | 별점의 근거로 쓰기엔 부족하다고 판단 |
| 구글 리뷰는 시설당 5개 | Places API 공식 문서 | 개수는 적지만 본문+별점을 얻는 쪽을 검토 |
| 구글 리뷰는 저장 금지 | Places API 정책 문서 (Place ID만 무기한 저장 가능) | 레포에 커밋하지 않고 호출 시점에 가져오는 구조 필요 |
| TMAP 보행자 경로 1일 1,000회 | 429 QUOTA_EXCEEDED 실제 발생 | 도보 시간 자체 계산을 포기하고 지도 앱 길찾기로 연결 |

## 기록 규칙

- 새로운 결정·검증·좋은 프롬프트가 나오면 **그때그때** 이 문서에 추가한다. 나중에 몰아서 쓰면 기억이 날아간다.

- AI가 틀린 것도 숨기지 않고 적는다. 그게 검증했다는 증거다.
- 숫자는 반드시 출처 파일을 같이 적는다.
